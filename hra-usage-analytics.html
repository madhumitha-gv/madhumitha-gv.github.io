Human Reference Atlas Usage Analytics

Behavioural analytics on 250,853 web events

The HRA dashboard reported traffic volumes but not how researchers actually move through the registration and exploration interfaces. This project turned raw Google Analytics events into navigation paths, interaction hotspots and a concrete discoverability gap.

RoleAnalyst, visualization team
Data250,853 GA events via BigQuery
ToolsPython, Pandas, BigQuery, PM4Py, Plotly
ClientHRA team, Indiana University

The problem

The Human Reference Atlas exposes several user interfaces: a Registration UI, an Exploration UI and the ASCT+B Reporter. The existing HRA dashboard provided traffic analytics but little insight into user behaviour: interaction patterns, event sequences and spatial usage trends were not visible.

Developers and UX designers needed to know which controls get used, which get ignored, and what paths users actually take, so that interface decisions could be driven by evidence instead of assumption.

The data

  • 250,853 event records exported from Google Analytics through BigQuery, covering multiple HRA interfaces through early 2025.
  • Nine attributes per event, including pseudonymous user id, hostname, page location, event timestamp, event name, category and label.
  • Core tracking fields were fully populated. Descriptive fields were patchier: hostname 99.3% complete, event category 83.2%, event label 82.3%.

Approach

  1. Cleaning. Removed page_view and generic webpage events, which carried no behavioural signal, cutting roughly 250,000 rows to the ~50,000 that described real interaction. Missing categorical values were filled with explicit placeholders rather than dropped, preserving dataset structure.
  2. Timestamps. Unix microsecond fields converted to UTC, with user_first_touch_timestamp backfilled from event_timestamp where the two overlapped.
  3. Label cleanup. Event labels arrived cluttered with long IRI prefixes and embedded metadata. Regular expressions stripped the prefixes and extracted the embedded attributes into their own fields, which stopped a large share of events collapsing into an uninformative "Other" bucket.
  4. Analysis across three dimensions: time, space and navigation flow.

What the visualizations showed

  • Stacked area chart of weekly event volume showed two clear activity peaks, in late December 2024 and late January 2025, driven by placement, node selection and session starts.
  • Heatmap of average daily clicks by hour revealed node selection concentrated in afternoon and late evening, while interface controls like opening search ran steadily all day.
  • Sankey diagram, built with PM4Py's heuristic miner, mapped event-to-event transitions and showed most journeys beginning at session start or first visit before moving into scrolling and node selection.
  • Sunburst and treemap exposed the hierarchy of interactions, with placement and node selection dominating, and detail like specific anatomical placements emerging at lower levels.

The finding that mattered

Specialised filters, such as those for sex and side, were used far less than the core placement and selection actions. That is a discoverability gap rather than a sign the features are unwanted, and it gave the UX team something specific to act on.

The activity peaks also pointed to concrete operational windows for system monitoring and feature rollouts, and the predictable early-session pattern validated the current onboarding flow as a baseline to measure future changes against.

Challenges

  • Variable-depth paths with more than four levels, or single-node sequences, cluttered the treemap and truncated it unhelpfully. Path depth was capped at four and singleton paths filtered out and logged separately, keeping the view auditable.
  • Raw event paths overwhelmed the Sankey with low-value flows. A heuristic mapping collapsed trivial paths so meaningful transitions stayed legible.

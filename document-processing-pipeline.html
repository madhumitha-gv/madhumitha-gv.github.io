Document Processing Pipeline

Neural denoising, OCR and compression as communicating microservices

Built in 24 hours at IU Hackathon 2026. A noisy scanned document goes in; clean, losslessly compressed text comes out. A custom U-Net denoises the page, TrOCR reads it, and an adaptive Huffman encoder written from scratch compresses the result.

The problem

Scanned documents come out noisy: blurred text, crumpled paper, stains, faded ink. Standard OCR fails on all of it. And even once you have clean text, you still need to store or transmit it efficiently.

Architecture

Four communicating services rather than one script, so each stage could be developed and tested independently under time pressure:

  • React dashboard for upload, noise-profile selection, metrics and a Huffman tree viewer.
  • FastAPI orchestrator handling JWT auth, a SQLite store, pipeline coordination and run history.
  • Stage 1, OCR: a classical filter matched to the noise profile, the U-Net denoiser, OpenCV projection-based line segmentation, then TrOCR inference.
  • Stage 2, compression: adaptive Huffman, returning compressed bytes, ratio, entropy, efficiency, the tree as JSON and the bit string.

The algorithms

U-Net denoiser. A custom encoder-decoder with skip connections, trained from scratch on the NoisyOffice dataset: 72 simulated noisy and clean document pairs spanning Gaussian, fold, crumple, wrinkle and pepper noise.

CRNN. Built independently to demonstrate the architecture end to end: convolutional blocks collapsing height to one so width becomes the time axis, two bidirectional LSTM layers, then greedy CTC decoding, which removes the need for character segmentation. Trained on 200k synthesised eMNIST word sequences.

Adaptive Huffman (FGK), implemented with no compression libraries. The frequency tree is built live, one symbol at a time, with an NYT sentinel node for unseen symbols and the sibling property maintained after every update, so encoder and decoder stay in sync with zero lookahead.
